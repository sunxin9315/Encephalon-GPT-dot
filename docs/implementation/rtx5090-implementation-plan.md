# Encephalon RTX 5090 实施路线与设计核查

日期：2026-10-17。依据上传压缩包中的设计资料。此报告区分设计要求、工程建议、待验证研究假设，不将文档数字作为实测结果。

## 1. 结论

可以开始硬件无关的 S0 工程基础，但不能把它称作完成了 S0 原配模型复现。当前包里只有 8 份专题设计、1 份索引和1份审阅交接说明，没有代码、权重、数据或实验结果。

RTX 5090 路线不是直接拼出一个现成全双工角色模型，而是：

1. B0：冻结 MiniMind-O 原配 Thinker–Talker，先复现其已有能力和接口。
2. 在 B0 上验证新增连接、持续状态和行为机制；同时可在文字任务上探索 B1。
3. B1：Qwen3-1.7B 作为语义主干，以原 MiniMind-O Talker 为初始化，重新训练语义与语音时序桥。桥接达标之后才替换 B0。
4. 按证据逐组解冻；不承诺 32GB 显存可同时完整 Adam 训练 B1 全部模块。

依据：01:13–18、121、174–176；02:335–351。仓库审阅交接说明中的“本轮只审阅”属于旧任务材料，不覆盖用户现在的实施请求；保留原始文档不改写。

## 2. 项目目标和不做什么

目标是持续的多模态交互，让人物经历、价值取舍、关系、记忆和动态情绪真正影响理解与行为，同时支持适当沉默、倾听、主动分享、全双工中止与异步复杂推理。不能以角色口吻或指定音色替代其余机制。

首期边界：中文为主、单用户、双视角、4–8 通道阵列；本地负责人格、记忆、策略与声音；云端仅推理，禁止用于本项目首期训练数据生成。没有物理执行器控制、强三维重建、完整多人语音分离或逐条在线修改共享主干。端侧设备是后续可选部署，不是 RTX5090 实施的先决采购。

依据：REVIEW_BRIEF:9–23；01:7–11、135、194；07:9–13；08:21–28、388–399。

## 3. 硬件和模型路线

### 硬件

设计规划为桌面 RTX5090 32GB、Linux/CUDA，主机内存64–128GB、可用 NVMe 2TB 起。这些是规划，不是已经验证的最低需求。实际需记录显卡型号/可用显存、驱动、CUDA、PyTorch、注意力算子、CPU/RAM/磁盘和音视频设备。

用户的 Ubuntu RTX5090 环境尚未准备好，因此当前可做工程基础，不能宣称已完成 GPU 测试。

### 必须锁定的 B0/B1 资产

| B1 语义主干 | Qwen/Qwen3-1.7B；2048 hidden、28层 | 原配基线通过后，文本机制与桥接试验 |

## 4. 分阶段里程碑

| 阶段 | 可交付物与训练范围 | 进入下一阶段的证据 |
|---|---|---|
| S0a 工程基础（当前可做） | 配置、版本清单框架、规范 schema、离线单调时钟回放、可见性过滤、身份/版本隔离、云端模拟器、播放游标、合成工程测试 | 确定性测试通过；未到达数据不可见；错误身份/过期结果不进入当前输出；未播内容不算说过；有界队列与错误处理 |
| S0b 原配复现（需模型和GPU） | 官方 B0 推理；小中英文语音/图像回归集；经人工复核的约200条短轨迹；原生处理器/codec/token 映射和数据来源 | 原配 I/O 可重复；目标/码本/时间/源文件一致；CER/WER、音色、自然度、RTF、首包、停止延迟、显存实测；不得混入新架构掩盖原配失败 |
| S1 冻结接口 | 感知 MLP、resampler、state-to-backbone cross-attention；既有主干冻结；独立小标签集验证 claim/policy 输出 | 损失下降且输出确实依赖输入；梯度到达新连接、冻结权重未更新；原任务回归不明显变差 |
| S2 持续机制 | 64×512 H_t、快速 Conv/GRU、交互/证据/等待/记忆控制头；8秒TBPTT | 对照VAD及无状态基线，误打断改善且漏打断/沉默不恶化；旧结果拒收和人物隔离回放零误用 |
| S3a 人物 | p/e/r/a 条件、人物 LoRA、事件评价、记忆使用；至少3个人物条件做交叉消融 | 未见情境有依据人物差异；无依据经历、跨人物泄漏和知识越界不过度增加；声音/身份/临时情绪可分别控制 |
| S3b B1 神经声音桥 | Qwen隐藏到Talker条件的时序 resampler/bridge；必要时解冻 embed_proj/指定Talker层 | 独立参考音频下CER、音色、漏词/循环、自然度和RTF达标；不靠级联TTS冒称神经桥已成功 |
| S4 分组联合 | 新机制与少量主干/Talker层，混合通用回归；B0可探索全部可微本地模块 | 增益超过回归，参数账本/梯度覆盖明确，实际显存和实时预算可控 |
| S5 长期积累 | 在线更新外部事件与动态状态，审核后离线巩固人物 adapter | 新经历正确使用、旧人格核心稳定；版本可回滚；不在线逐条更新共享主干 |
| 可选端侧分布式 | 同机基线后逐项迁移采集/播放、视觉/环境声，再决定语义编码 | 保持相同输入/窗口/人物/模型；实际尾延迟或资源有收益，无持续积压，否则回退 |

依据：02:17–30、335–370；01:178–195；07:365–403；08:357–395。

### 不应合并的验收

1. 数据契约与测试通过，不等于 B0 模型已复现。
2. 能放进显存，不等于实时。
3. 模型单次 forward 快，不等于完整交互和停止快。
4. 能切换人物包，不等于人物表现可信。
5. 有门控和证据字段，不等于绝对不会幻觉。
6. 合成/模拟工程 fixtures，不等于人工审核轨迹或合格训练集。

## 5. S0a 的具体实现契约

### 公共信封和时钟

- 使用 README 的规范字段：schema_version；persona_id/persona_version；session_id/state_version；event_start_ms/event_end_ms；available_at_ms；validity/quality；request_id/claim_ids；source_ids/provenance。
- 全部在线时间是同一会话的单调毫秒，不混入 UTC、故事时点或设备私有时钟。跨会话历史另存UTC；跨设备必须有映射及误差界。
- decision_ms 时只能消费 available_at_ms≤decision_ms 的信息。采集已结束不代表编码已完成或网络已到达。
- 输入可见性mask、目标loss_mask、有效长度分开。未来标签只能进loss，不进输入。
- 公共 validity 使用 valid/missing/stale/corrupt；正常静音是有效观测。失败原因独立记录。

依据：README:62–80；01:78–91；02:83–85、216–222；08:163–204。

### 版本、异步和结果接纳

- observation_id/source_id+revision 支持修订和去重，重叠语音窗口不能重复成为新事件。
- 所有异步返回检查人物、人物版本、会话、请求关联、状态/前提依赖和有效期。
- 不宜把每次 H_t tick 变化都当作全部旧请求立即失效。应明确请求依赖快照或依赖版本；若第一版采用保守拒收，应公开这一限制，不能声称完成正确适用性判断。
- queued 是本地待派发，running 是已发出在途；不模拟为可观测远端计算百分比。future_return_at 必须仅留在模拟器私有调度数据里。
- succeeded 仅是通信成功，不自动使 claim supported；timeout/offline 也不改变事实依据门槛。

依据：README:84–89；01:85、117、131；02:170、269、273–285。

### 播放与人物切换

- generated、queued、played 三边界分开。音频包绑定人物/版本/会话/utterance/sequence。
- 确认实际播放才推进 played；停止只清理未播队列，已播内容不可撤回，只能随后纠正。
- 人物切换按事务顺序：拒绝旧表达，停止未播队列，保存旧已播和状态，隔离旧请求，换记忆/adapter/声音条件，重建缓存，自检身份一致再输出。
- 工程防抖和网络策略输出分别记录，不将测试规则冒称训练后的自主策略。

依据：01:119–123、133；07:83–91、142；08:214–222。

### 最小离线测试矩阵

应含：未到达但时间较早的特征；有效静音/丢包区别；单视角缺失；重复窗口新revision；乱序/重复消息；人物切换期间迟到云端结果；问题前提改变；云端超时仍未确认；生成未入队/入队未播；停止后的旧包；跨会话游标；PersonPack非法路径/缺来源/占位revision；队列上限；可重复随机seed。

所有当前自行生成用例标记 synthetic/mock，报告场景数与测试数，不能称“已完成200条人工审核集”。

## 6. 关键歧义、冲突与风险

| 事项 | 类型与定位 | 最小处理 |
|---|---|---|
| validity 词表不统一 | 工程缺口：01:80 与02示例使用present/failed；README:73及08:200使用valid/corrupt | 以README为公共规范，显式alias迁移；failed保留失败原因，不误把无包和坏包都当正常值 |
| 请求状态版本粒度未定义 | 工程缺口：01:131与README:87 | 定义依赖快照、取消/失效原因及TTL；不能仅凭正在运行或接口成功接纳 |
| 编码器/模型名称不是锁定版本 | 前置证据缺口：01:40–54、192 | 只读核验官方仓库、模型卡、配置、依赖与license，再生成真实lockfile；不得编造commit/hash |
| B1声学桥未验证 | 高影响研究假设：01:16、121、193；02:327–333 | 用匹配原配教师条件与独立语音目标的小集先验证，再考虑解冻Talker；失败时保留B0或显式文本结果 |
| 短窗SenseVoice非原生流式 | 高影响研究假设：01:46、85、91、193 | 比较0.8/1.6/3.2秒与完整句；延迟从真正可判别时刻计；快侧路不假装已理解语义 |
| S0叙述含“小集过拟合”，README原配阶段又要求不更新模型 | 阶段表述歧义：02:341 vs README:95 | 分成纯推理复现和独立训练管线/过拟合测试；不能用训练后结果冒称原配基线 |

| 人物规模是建议不是保证 | 证据限制：02:53–65 vs07:239–251 | 从小规模合法素材和明确mock对照起，来源不足则只验证有依据子集 |

| 常驻两套主干/盲目扩大模型 | 资源风险：01:18、56、174–176 | B0/B1分配置；数据/激活/权重分别计量；不默认全量B1训练 |

## 7. 安全与隐私工程建议

以下是设计中尚未完整定义的实施事项，不表示已有安全功能：

- 默认离线、无设备采集、无付费API。真实摄像/麦克风、目标人物素材和声音适配在确定设备、参与者授权、用途和保存范围后启用。
- 原始音视频、人物经历、说话人向量和关系记忆按命名空间隔离；制定保留期限、可删除/纠正路径、备份策略和访问控制。不要把私密素材、完整录音、密钥提交到Git或运行日志。
- 云端请求只发送明确必要且已授权的数据；密钥使用环境/密钥管理，不写进模型清单。未配置云端时应保持可复现的离线fixture路径。
- 将云端输出、检索文本和人物资料作为不可信数据，不允许其变成系统指令、执行代码、修改权限或直接驱动物理动作。
- 新模型/数据导入校验路径、大小、hash、tensor形状与dtype；优先安全权重格式。执行外部仓库代码、pickle载入或trust_remote_code前需要审查来源和实际代码。
- 如果以后增加端侧网络，需认证、传输保护、payload长度和shape校验、序号防重放、有界队列与资源限制。文档的时间戳与revision不能替代网络身份认证。
- 真人/角色素材权利、研究限制和派生使用条件随特征与checkpoint保存。未经确认不将研究受限数据混入可发布模型。
- 对用户说明这是人物模拟系统；情绪状态和模型评分不是对真实人物内心或生物机制的事实判断。

依据：07:70–81、128–132、204–231、315；02:34–49；08:163–204。上述建议属于实现前风险控制，不是法律结论。

## 8. GPU 就绪后的首次执行清单

1. 只读采集硬件/系统信息并保存，不先安装整套猜测版本。
2. 核验官方 B0 代码、模型入口、模型格式、需要的额外encoder与音频库，形成固定revision及依赖方案。
3. 创建隔离环境，安装已核验依赖；运行PyTorch CUDA、BF16、基础attention与音频处理自检。
4. 下载最小B0权重/对应小分片，逐文件记录hash及许可，原始数据只读。
5. 先跑官方原配例子和本地回归，记录输出/失败；不改模型掩盖首次问题。
6. 记录完整参数账本、加载后的真实shape和码本、实际峰值显存与运行路径。
7. 对合法样本执行音频回归、停止/队列实验和30分钟长运行；首轮不用真实个人素材也能先验证大部分模型机制。
8. 整理与S0a的差异、修复数据适配，不改变公共因果/身份/已播契约。
9. 基线通过再进入S1；未通过则报告具体硬件/库/模型/数据阻塞，不宣称阶段完成。
