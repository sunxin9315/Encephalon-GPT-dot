这是审阅任务的背景和工作说明，不是审阅结论。设计材料位于 `D:\gpt_project\encephalon\docs\design`；相对路径链接适合随整个 `docs` 目录一同移交。

## 1. 请先理解项目要研究什么

Encephalon 是一个探索性的多模态 AI 脑模型研究项目。研究目标是通过专用神经网络模块及可训练连接，构成具有持续状态、经历、人格、情绪和自主交流能力的整体模型，并逐步探索本地神经路径的联合训练。

预期交互如下：

1. 持续接收多视角图像、阵列麦克风和文字。音频包括讲话和环境声音，需要利用音色区分讲话人，并保留韵律及非语言线索。
2. 保持跨时间的内部状态，理解正在发生的事情，同时能够讨论未出现在眼前的话题。
3. 根据目标人物的经历、价值判断、关系和当前情绪选择如何理解事件、是否交流、说什么，以及如何表达。
4. 支持自然倾听、沉默、简短反馈、讨论和有意义的主动分享。不能把持续感知等同于不断播报眼前场景，也不能靠反复填充话术制造“实时互动”。
5. 用指定人物音色输出带语气的声音，输入与输出全双工；模型自主决定继续、暂停、停止、澄清或等待。
6. 有快速反应路径，也有较慢的深度推理路径。首期复杂推理按需调用外部 API，本地模型识别需要等待确认的具体结论，并依据实际可用信息决定怎样交流。
7. 保留目标人物的部分初始经历，并在后续交互中持续积累、修正和压缩记忆。时间、事件重要性、人物意义和未来用途共同影响保留程度。
8. 能够通过替换人物相关资产更换目标人物；人格、记忆、关系、音色及运行缓存需要保持身份隔离。
9. 可选模块无输入或失效时能够降级。未来动作控制仅预留接口，本期不实现小脑或执行器控制。

“更符合人类逻辑”在本次审阅中应转化为可检验行为：因果时间正确、经历有依据、价值选择相对稳定、情绪随事件连续变化、关系与话题延续、交流时机适当、能够修正错误。请审查这些行为是否有实际的结构、数据、训练与评价支撑。

用户明确将本项目定位为创新探索。审阅应评估现有方案能否形成可证伪的研究路线，允许提出不同结构；相关能力没有现成可插拔模型，本身不足以判定研究不值得进行。与此同时，新增一个模块名称或一个潜变量，也不能作为该能力已经实现的证据。

## 5. 当前方案的简要技术图景

以下是现有设计的概括，供建立阅读框架，不代表审阅者需要接受这些结构。

### 5.1 共享路径

感知编码器产生特征，经投影、重采样、时间/来源/质量编码进入持续状态 `H_t`；本地语义主干、交互策略和证据判断读取状态。人物与记忆条件影响事件评价、检索、交流意图和表达；获准表达的计划经承诺连接送入 Talker/音频解码，实际播放结果再反馈给状态。

需要重点自行训练的部分包括：持续状态更新、人格与事件评价、情绪动态、记忆读写压缩、交流时机、结论可表达性、云端等待策略以及异源神经连接。已有模型主要提供感知、语言与声学基础。

### 5.2 三档候选路径

| 档位 | 文档当前候选 | 请特别核验 |
|---|---|---|
| RTX 5090 | MiniMind-O 原配 Thinker–Talker 作基线；Qwen3-1.7B 加新连接作研究分支；SenseVoice、SigLIP、BEATs、CAM++、Mimi 等提供专用能力 | 异源语义与声学连接是否可训；窗口感知与实时决策边界；现有能力是否被夸大 |
| RTX PRO6000 | 以 MiniCPM-o 4.5 原配路径为基础，增加持续状态、人物、控制和表达条件 | 特征接口、原配流式状态、冻结后的输入梯度与新条件注入是否兼容 |
| 大型集群 | 以 Qwen3-Omni 为原配基线，新增研究模块；指定人物音色的进阶分支研究 CosyVoice3 神经桥 | 总参数与激活参数区别；原生音色能力；跨模型码本/条件对齐；扩展训练依据 |

具体版本、参数量、许可证和接口以审阅时的官方仓库、模型卡、配置与源码核验为准。请把“名称出现在文档中”和“已证明能按本项目方式使用”区分开。

### 5.3 人物与记忆

当前采用混合 PersonPack：共享通用主干＋人物适配参数＋可追溯初始记忆 `M0`＋后天记忆 `M+`＋人物独立的动态状态与声音条件。具体经历主要保留为有来源的数据，稳定行为倾向通过条件与适配参数表达。

当前人物向量、情绪、关系和事件评价的起始维度分别为 `p=256、e=32、r=64、a=16`，它们是待消融的设计选择，不是已证实的人格或情绪机制。初始记忆应影响注意、理解、价值判断、记忆选择与主动分享；只在回答中引用人物台词，不足以验证这些作用。

### 5.4 分布式部署

08 优先把冻结感知编码器放端侧，可训练连接、持续状态、人格情绪、语言主干和声学生成留在桌面。网络传神经特征与时间/质量元数据，不限定为文字接口；长期记忆主要在主机内存和 SSD。

这条路线的预期收益是感知常驻、计算分担和部分内存释放。端侧统一内存不自动变成桌面 GPU 的远程显存池。当前轻量感知权重占比较小，节省多少显存、是否值得采购，应依据模块清单和实测，而非仅看设备标称容量。

## 6. 审阅的重点问题

### 6.1 整体结构与可学习性

- 每条关键路径是否说明输入、输出、状态、维度、时间、缺失处理与训练信号？是否存在只有模块名称而没有有效机制的部分？
- 冻结表征中是否有后续任务所需的信息？仅训练连接可以对齐哪些能力，哪些必须解冻或更换编码器？
- 新持续状态是否相对扩大上下文、普通循环状态或简单检索有明确可检验的作用？
- “端到端交互”“可联合优化的本地神经路径”“外部工程/离散边界”是否分别说清楚？

### 6.2 人格、经历与情绪的因果作用

- 人物记忆与价值条件是否真正影响事件解释、选择、交流时机和关系行为，还是主要改变措辞与声线？
- 能否通过交换人物、记忆、音色和情绪条件的对照，区分各部分的实际作用？
- 动态情绪与稳定人格是否有清楚的时间尺度和更新边界？是否会重复响应同一观测，或因一次误识别造成永久漂移？
- 真人材料、虚构角色世界线、角色知识时点、旁白与声优身份是否处理清楚？
- PersonPack 更换是否需要重训共享模型？不同主干之间哪些资产可共享，哪些参数必须重训？

### 6.3 初始和后天记忆

- 初始记忆、交互经历、推断、解释和事实修正是否区分，能否追溯到来源？
- 上下文、持久状态、检索与压缩分别承担什么，是否存在重复存储或遗漏关键责任？
- 压缩是否保留重要事件、否定、时间、人物关系及纠错关系？重要性标注和未来效用是否可获得？
- 如何评估误写入、自我强化的错误回忆、重复分享、知识边界泄露和长期漂移？

### 6.4 流式、全双工与因果时间

- 原生因果编码和已到达窗口重算是否混淆？快侧路的更新频率是否被误当成同等语义分辨率？
- 每个动作是否只使用当时已经可用的信息？重叠窗、迟到帧、未来剧情或训练标签是否造成时间泄漏？
- 自主继续/停止是否有数据与损失支持，能否区别旁人说话、背景声、附和与真正插话？
- 已生成、已入队、已播放是否分开？打断、恢复与人物切换后，语义/KV/声学缓存如何处理？

### 6.5 云端推理、校准与表达

- 本地如何判断某个结论需要确认？训练标签和校准方法是否足够，而不仅是增加一个“置信度头”？
- 外部 API 可用状态是否真实可观察？是否把未知远端状态或模拟器已知的未来返回时刻当输入？
- 云端错误、互相冲突、返回过期或请求前提变化时，模型如何处理？
- 如何同时测未经支持断言与过度等待/拒答，防止“始终不回答”获得好分数？
- 承诺连接能否限制不应表达的信息，旁路或隐状态是否仍会把未经支持的内容带入声音？

### 6.6 数据、损失与梯度

- 每个待训练模块是否对应具体样本字段、有效标签、训练目标和评价方式？公开数据实际覆盖哪些能力，哪些需要自建？
- 数据入口、许可、申请条件与媒体可获取性是否有可靠来源？公开数据是否只是相关，实际缺少关键标签？
- 每项损失的符号、维度、归一化、mask、权重和梯度去向是否正确？是否存在写了目标但梯度无法到达的情况？
- 冻结权重与禁止输入梯度是否混淆？硬检索、采样、数据库与 API 边界如何处理？
- 教师强制、缓存特征和离线完整片段是否造成训练与真实流式推理不一致？
- 人物、来源事件、会话、相邻窗口、声学参考与目标、未来事件是否有合理的训练/验证/测试隔离？

### 6.7 硬件、网络与成本

- 推理权重、KV、激活、工作区，与训练梯度/优化器状态是否分别计量？GB/GiB、量化精度和上下文假设是否一致？
- 参数激活比例是否被错误当成权重存储比例？吞吐提升是否被错误当成单会话延迟降低？
- 端侧切分的特征尺寸、频率、切片数量和协议开销是否完整？输入窗口和端侧计算耗时是否进入延迟预算？
- 所称可释放显存是否只包含确实迁移的模块？是否漏算接收侧缓存或把统一内存当成自动共享显存？
- 是否存在成本更低且保留研究目标的实验部署？请给出可比较条件，不凭未核实报价下采购结论。

### 6.8 研究收益、消融与跨文档一致性

- 哪些假设是项目成功最依赖、目前最缺证据的？是否可通过小模型和少量轨迹先验证？
- 与原配模型、简单人格提示、普通 RAG、纯时间遗忘、无情绪动态、规则式打断等对照相比，新增结构的收益能否分辨？这些对照服务于验证，不自动替代研究目标。
- 各对照的数据、上下文、参数、计算和延迟预算是否可比？
- 不同文件对共享字段、人物维度、阶段冻结范围、声学体系和时间语义是否一致？硬件档有意差异与无意矛盾要分开。

## 7. 建议的审阅方法与证据要求

1. 先列出研究目标、明确约束、当前假设和实际已有证据，确认自己理解的项目与文档一致。

3. 对影响判断的模型事实、结构尺寸、流式行为、音色能力、训练入口和硬件规格，查官方模型卡、配置、源码、论文或厂商资料。记录 URL、日期和可获得的 revision；无法核实则明确标注，不猜测。
4. 对尺寸、容量、码率和时序做独立计算。分清理论载荷、规划预算、实测性能和待验证目标。
5. 对新增研究结构，说明为何可能有效或失败，提出能够区分解释的对照实验。
6. 先完成整体覆盖，再按影响整理结果。列出已读、部分阅读和未核验的范围，避免用局部检查代表全套审阅。

审阅意见分为四种类型：

- **事实或逻辑错误：**有来源、数学或明确依赖关系证明当前表述不成立。
- **工程缺口：**目标可能成立，但缺少关键接口、时序、数据或实现条件。
- **证据不足：**当前缺乏必要依据，需要源码核验、计算或实验才能判断。
- **研究假设：**尚待检验的机制选择；给出预期作用、风险、消融与失败后的替代路径。

“尚无证据证明有效”和“已经证明不可行”应采用不同结论。创新价值也需要与现有研究比较后陈述，不能仅因文档提出了模块名称就声称原创。

## 8. 希望收到的审阅结果

请输出一份可执行的审阅报告，至少包括：

1. **总体判断：**是否适合进入首轮实验；分别评价研究目标、当前架构、训练可行性、资源约束及证据完整性。
2. **最重要的问题：**按影响排序，优先列出影响核心目标或首轮实验的事项，不要求凑满固定数量。
3. **逐项发现：**给出文档位置、具体问题、证据、影响、最小修改建议和验证方式。
4. **跨文档一致性表：**列出有意差异、实际冲突和待统一字段，尤其是架构与训练之间的对应关系。
5. **最小验证实验：**围绕最关键的未验证假设，给出必要输入/标签、对照、指标、资源估算、停止或继续条件；明确未实测部分。
6. **研究路线调整：**哪些模块应优先验证，哪些可以延后，哪些应替换；说明是否改变原有研究目标。
7. **覆盖与限制：**实际阅读/核验范围、缺少的信息、尚不能判断的结论。

每条重要发现建议使用以下格式：

```text
编号：R-01
优先级：P0 / P1 / P2 / P3
类型：事实或逻辑错误 / 工程缺口 / 证据不足 / 研究假设
定位：文件相对路径 + 章节或行号
问题：具体表述及成立条件
证据：文档依据、官方来源/源码、计算或可复现观察
影响：影响哪些能力、训练阶段或资源预算
建议：最小必要修改；必要时另列结构替代方案
验证：能够确认或推翻该判断的检查/实验
置信度与限制：已确认、较强推断或需要实验；说明依据
```

优先级约定：P0 表示不解决就会使当前关键路径无法成立的已确认问题；P1 表示首轮实验前应处理的重要缺口或高影响风险；P2 表示可以在后续阶段改进的问题；P3 表示表达、结构或次要维护问题。优先级与置信度分别记录，不能仅因某方向尚未实验就列为 P0。

本次不要求审阅者维护现有选型。可以提出较大调整，但应说明它解决什么、牺牲什么、需要怎样验证，以及是否仍保留人物经历、价值判断、持续情绪和自主全双工这些研究目标。
